# NEXTRA Final SIH Prototype Status

**Date:** 2026-09-22  
**Status:** End-to-end prototype validated

## Completed Features

- FastAPI backend with SQLite/SQLAlchemy persistence.
- JWT authentication for Admin, Field Officer, Logistics, and Driver roles.
- Role-based authorization and assigned-area restrictions.
- Role-specific dashboards with live database KPIs.
- Admin user management and Field Officer creation.
- Field reports with multipart image uploads.
- Verification queue with Admin/Field Officer review permissions.
- Targeted notifications for reports, verification, risk, alerts, and shipment delays.
- Live Leaflet map with vehicles, drivers, shipments, reports, risks, alerts, routes, affected roads, clustering, filters, and area focus.
- Risk intelligence and weather-to-risk cascade.
- Logistics transportation requests, shipments, fleet, drivers, and route information.
- Weather and accessibility views.
- Offline field-report buffering and synchronization.
- Audit logging for governance actions.
- Loading, empty, and error states for dashboard and operational views.
- Responsive dashboard behavior for desktop, tablet, and mobile layouts.
- Invalid-token startup gating and logout session cleanup.

## Startup Commands

From the repository root:

```powershell
Set-Location backend
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Open the frontend at `http://127.0.0.1:8000/login.html`.

The frontend is served by FastAPI. No separate frontend server is required for the current prototype.

## Database Seed Command

From the repository root:

```powershell
Set-Location backend
python -m app.database.seed
```

The seed script is idempotent. Use its reset option only when intentionally rebuilding demo data:

```powershell
python -m app.database.seed --reset
```

## End-to-End Verification

Validated scenarios included:

- Admin login, dashboard, menus, notifications, user management, Field Officer creation, verification, map, risk, and reports.
- Newly created Field Officer persistence, assigned area, role, and login.
- Field Officer area dashboard, area reports, verification permission, and map access.
- Driver assignment, own vehicle lookup, map, alerts, weather, area officer, and report workflow.
- Logistics shipments, drivers, vehicles, transportation requests, alerts, and route data.
- Driver report upload through backend, SQLite report/verification records, physical image storage, Admin and assigned Field Officer notifications, map report marker, and risk/accessibility update.
- Assigned Field Officer verification, Driver notification, database status update, and audit log.
- Weather risk cascade, alert generation, map/dashboard availability, and targeted risk notifications.
- Unauthorized API access and role restrictions.
- Logout and invalid-token redirect behavior.
- `/api/health` and `/docs` availability.

The visible E2E API/database run completed 43 of 45 assertions directly. The two reported non-passes were test-harness assumptions: the upload was checked relative to the caller instead of `backend/uploads`, where it was present, and missing credentials correctly returned HTTP 403 rather than the harness's expected 401. Invalid credentials/tokens correctly return HTTP 401.

Browser checks completed with all four roles loading successfully, valid-session API failures at zero, console errors at zero, page errors at zero, and map markers/controls rendered.

## Known Limitations

- The application uses seeded/demo data rather than production logistics integrations.
- The map uses external Leaflet tile and marker-cluster assets and requires network access for those assets.
- The notification system is polling/refresh based, not a WebSocket or push notification service.
- The risk engine is deterministic and database-driven; it is not connected to a live external AI or weather provider.
- Some compatibility code retains localStorage fallback data for legacy modules and offline operation.
- Dependency deprecation warnings remain for FastAPI `on_event`, Pydantic class-based config, and related library APIs; they do not block current functionality.

## Simulated Features

- AI image analysis and confidence values are simulated deterministically for the prototype.
- Weather readings and seeded operational telemetry are demonstration data.
- Offline mode and synchronization are locally simulated through IndexedDB/localStorage before backend replay.
- Risk notifications and route changes are generated by the local deterministic risk engine.
